# ДЗ11. Библиотека со слоистой архитектурой

Требуется Go 1.22 или новее. Используется только стандартная библиотека.

## Запуск

Из корня репозитория:

```sh
cd homework-11/code
go run ./homework/fat
```

Сервис слушает `localhost:8080`. В другом терминале отправьте запрос:

```sh
curl -i -X POST http://localhost:8080/loans -H 'Content-Type: application/json' -d '{"book_id":1,"reader_id":2}'
```

В PowerShell можно использовать встроенную команду:

```powershell
Invoke-WebRequest -Method Post -Uri 'http://localhost:8080/loans' -ContentType 'application/json' -Body '{"book_id":1,"reader_id":2}'
```

Успешная выдача возвращает `201` и JSON вида `{"due":"YYYY-MM-DD"}` с датой через 14 календарных дней. Повторная выдача той же книги и попытка взять четвёртую книгу возвращают `409`. Если срок любой книги на руках у читателя уже истёк, новая выдача также возвращает `409`, даже когда до лимита ещё есть место. Сервис сравнивает текущее время с сохранённым сроком возврата. Неверный JSON или нулевой обязательный ID дают `400`.

Остановка — Ctrl+C. Хранилище находится в памяти и очищается при перезапуске. Не запускайте другой сервис на том же порту, включая клинику из лекции.

После обработки запроса сервер пишет в журнал метод, путь, HTTP-статус и затраченное время. Например, при успешной выдаче строка заканчивается на `POST "/loans" 201 150µs`.

## Проверки

Все команды выполняются из `homework-11/code`:

```sh
go fmt ./...
go test ./homework/fat/
go test ./homework/fat/usecase/
go test ./...
go vet ./...
go list -f '{{.ImportPath}}: {{.Imports}}' ./homework/fat/...
```

Исходный `main_test.go` сохранён без изменений. В `usecase/library_test.go` — обязательный табличный тест с новой подделкой хранилища для каждого случая: успешная выдача, занятая книга, лимит читателя. Проверяются ошибка через `errors.Is`, число сохранений и срок между границами времени вызова плюс 14 дней.

## Распределение ответственности

| Пакет | Ответственность |
|---|---|
| `entity` | `Loan`, `ErrTaken`, `ErrTooMany`, `ErrOverdue` |
| `usecase` | Интерфейс `Repository`, правила выдачи, проверка просрочки, лимит 3 и срок 14 дней |
| `repository` | `Memory`, хранение в map, синхронизация отдельных операций |
| `delivery` | JSON, проверка обязательных полей, HTTP-статусы и формат даты |
| `main` | Сборка repository → usecase → delivery в `newMux()`, запуск сервера |

Usecase импортирует только стандартные `context`, `fmt`, `time` и пакет `entity`. В delivery нет хранилища, в repository — правил библиотеки. Каждый `newMux()` получает собственное хранилище.

Ответы на вопросы условия расположены в конце `main.go`.

## Ограничение конкурентной выдачи

Методы хранилища блокируют map по отдельности. Два одновременных запроса могут пройти проверки и получить `201` для одной книги либо превысить лимит одного читателя.

Для устранения логической гонки нужны согласованные проверки и сохранение в одной критической секции или транзакции. Правила при этом должны оставаться в usecase. Этот механизм в обязательную часть ДЗ не входит и здесь не реализован; вопрос разобран в `main.go`. Несколько процессов также не согласуются через локальный Mutex и разные map.

## Схема бронирования столика

`POST /reservations` принимает `table_id`, `guests` и `time`. Время передаётся в RFC 3339, например `2030-01-15T19:00:00+03:00`. Успешный ответ — `201 Created` с телом `{"id":1}`.

| `delivery` | `usecase` | `repository` |
|---|---|---|
| Разбирает JSON и проверяет, что все поля есть: `table_id` и `guests` положительные, `time` содержит дату и время. | `Reserve` проверяет лимит в 8 гостей. Сравнивает время брони с текущим временем и границей `now.AddDate(0, 0, 30)`. Момент ровно через 30 календарных дней допустим. | `IsTaken(ctx, tableID, at) (bool, error)` ищет бронь этого столика на указанный момент. |
| Передаёт разобранные поля в `Reserve`. Преобразует результат в HTTP-статус и JSON. | Спрашивает хранилище, свободен ли стол, и сохраняет бронь. Если место уже занято, возвращает `ErrTableTaken`. | `Save(ctx, reservation) (int, error)` сохраняет бронь и возвращает ID. Хранилище гарантирует уникальность пары «столик, время» при записи. Если два запроса одновременно увидели свободное место, записывается только первый. Usecase переводит конфликт при записи в `ErrTableTaken`. |

| Результат | HTTP |
|---|---|
| Неверный JSON, пропущенное поле, неверный формат или неположительные `table_id` и `guests` | `400 Bad Request` |
| Больше 8 гостей, время в прошлом или дальше 30 дней | `400 Bad Request` |
| Столик занят на запрошенное время | `409 Conflict` |
| Сбой хранилища | `500 Internal Server Error` |
| Бронь сохранена | `201 Created`, `{"id":1}` |

В этой схеме слот определяется точным временем начала. Длительность брони в задании не указана.

## HasDuplicate

Множество реализовано через `map[int]bool`. При обходе сначала проверяю, встречалось ли число. Если да, возвращаю `true`. Иначе запоминаю его. После полного обхода без совпадений возвращаю `false`.

Проверка стоит перед добавлением, чтобы текущее число не было принято за свой собственный повтор.

Например, для `[-3, 2, -3]` сначала запоминаются −3 и 2, а последнее число уже присутствует в карте. Ответ — `true`.

Пусть `n` — число элементов. Ожидаемое время — `O(n)`, потому что один раз обхожу вход, а поиск и запись в хеш-таблице в среднем занимают `O(1)`. Дополнительная память — `O(n)`, когда все числа различны.

## TwoItems

Словарь хранит соответствие `цена → индекс ранее просмотренного товара`. Для очередной цены `price` вычисляю недостающую сумму `need = k - price`. Если такая цена уже есть в словаре, возвращаю её индекс, текущий индекс и `true`.

Использую `previous, ok := seen[need]`, потому что индекс 0 — допустимый ответ. Проверять наличие ключа по ненулевому индексу нельзя.

Текущую цену записываю после проверки. Поэтому один и тот же товар не будет использован дважды, а возвращаемые индексы всегда упорядочены `i < j`. При отсутствии пары возвращаю `0, 0, false`. При нескольких парах подходит любая.

Например, для `[4, 9]` и суммы 13 сначала запоминаю `4 → 0`. Для цены 9 ищу 4 и получаю ответ `0, 1, true`.

Пусть `n` — число товаров. Ожидаемое время — `O(n)`, дополнительная память — `O(n)`. Для каждой цены выполняю постоянное число операций карты.

## BracketsOK

Стек хранит открывающие скобки. При открывающей скобке добавляю её в конец среза. При закрывающей проверяю, что стек непустой и сверху лежит нужная открывающая скобка, затем снимаю её.

Словарь из трёх пар задаёт соответствия `')' → '('`, `']' → '['`, `'}' → '{'`. Остальные символы пропускаю.

Стек подходит, потому что последняя открытая скобка должна закрыться первой. Для `([)]` после чтения `([` сверху находится `[`, которая не подходит для `)`. Ответ — `false`.

В конце возвращаю `true` только при пустом стеке. Так обнаруживаются оставшиеся незакрытые скобки.

Пусть `n` — число символов строки. Время — `O(n)`, дополнительная память — `O(n)` в случае множества открывающих скобок. Каждая скобка добавляется и снимается не больше одного раза. Добавления через `append` дают линейную суммарную работу.

## IsPalindrome

Преобразую строку в `[]rune`, чтобы корректно сравнивать кириллицу. Два индекса начинаются с концов этого среза. Если символы различаются, возвращаю `false`. При равенстве сдвигаю оба индекса к середине.

Когда индексы встретились или пересеклись, все симметричные пары совпали, поэтому возвращаю `true`.

Например, в слове `казак` сначала сравниваются `к` и `к`, затем `а` и `а`. Центральную `з` сравнивать с другим символом не требуется.

Регистр, пробелы и знаки учитываются как есть. Поэтому `Аа` и `а!` дают `false`, а `а а` и `!а!` дают `true`.

Пусть `n` — число символов. Время — `O(n)`, включая преобразование строки. Дополнительная память — `O(n)` для `[]rune`. Сами два указателя занимают `O(1)`.

## IsAnagramSort

Создаю отдельные `[]rune` для обеих строк. Если число символов различается, возвращаю `false`. Иначе сортирую оба среза через `slices.Sort` и сравниваю через `slices.Equal`.

Если наборы символов с учётом количества одинаковы, после сортировки получатся одинаковые последовательности. Например, `липа` и `пила` после сортировки имеют одни и те же символы в одном порядке.

Пусть `n` и `m` — числа символов двух строк. В худшем случае время — `O(n log n + m log m)`: преобразование и сравнение линейны, основную работу выполняет сортировка. Дополнительная память — `O(n + m)` для двух копий символов.

## IsAnagramMap

Словарь `map[rune]int` хранит частоты символов первой строки. Затем прохожу по второй строке и вычитаю её символы. Если нужного символа уже не осталось, возвращаю `false`.

После второго прохода проверяю, что все частоты равны нулю. Это обнаруживает и символы, которые остались только в первой строке.

Например, для `ааё` словарь содержит `а → 2`, `ё → 1`. В строке `аёё` вторая буква `ё` уже не может быть вычтена, поэтому ответ — `false`.

Пусть `n` и `m` — числа символов строк, а `u` — число разных символов первой строки. Ожидаемое время — `O(n + m)`, включая заключительную проверку `u ≤ n` частот. Дополнительная память — `O(u)` для словаря. Полные копии строк в `[]rune` здесь не создаются.

Для обеих реализаций регистр, пробелы и знаки значимы. Сравниваются значения `rune`; специальная нормализация Unicode не выполняется.

### Какой способ выбрал бы на работе

Для проверки самого факта анаграммы выбрал бы словарь частот. Он позволяет получить ожидаемое линейное время и хранит только разные символы. Сортировку выбрал бы, если отсортированные символы понадобятся и для дальнейшей обработки. Сортировка также даёт предсказуемую оценку времени без предположения о средней стоимости операций карты.

## Необязательная часть

### CanFulfill

Реализован словарь остатков `товар → количество`. Сначала считаю товары склада, затем для каждой позиции заказа проверяю остаток и уменьшаю его на один. Недостаток хотя бы одного товара даёт `false`.

Пустой заказ можно выполнить даже при пустом складе. Повторы в заказе расходуют отдельные экземпляры товара.

Пусть `n` — число товаров склада, `m` — число позиций заказа, `u` — число разных товаров склада. При ограниченной длине названий ожидаемое время — `O(n + m)`, память — `O(u)`. При произвольной длине названий нужно дополнительно учитывать стоимость хеширования строк.

Собственные тесты проверяют пустые входы, заказ двух одинаковых товаров, недостаточное количество и отсутствующий товар.

### Минимальный стек

`MinStack` содержит два параллельных среза. В первом лежат значения, во втором — минимум для каждого соответствующего уровня стека.

`Push` добавляет значение и минимум между ним и прежним минимумом. `Pop` укорачивает оба среза и возвращает снятое значение. `Minimum` возвращает последний элемент среза минимумов.

Повторяющиеся минимумы сохраняются на каждом уровне. Например, после добавления `5, 3, 3, 7` срез минимумов содержит `5, 3, 3, 3`. После удаления 7 и одной тройки минимум всё ещё 3, после удаления второй тройки — 5.

`Minimum` и `Pop` работают за `O(1)`. `Push` работает за `O(1)` амортизированно; отдельное добавление может потребовать расширения среза. Память — `O(n)`, где `n` — максимальное число одновременно хранившихся элементов. После снятия элементов ёмкость срезов может сохраняться.

По контракту `Pop` и `Minimum` вызываются для непустого стека. Нулевое значение структуры готово к `Push`.

Дополнительные тесты проверяют повторяющийся минимум, отрицательные числа, один элемент, полное опустошение и повторное заполнение стека.

### Найди баг

Исходный алгоритм для `[1, 2, 2, 3]` напечатает `[1, 2, 3]`.

После удаления элемента на позиции 1 вторая двойка сдвигается на ту же позицию. Безусловное увеличение `i` сразу переводит обход к тройке, поэтому сдвинутая двойка пропускается.

Исправление — увеличивать индекс только тогда, когда элемент сохранён. После удаления повторно проверять ту же позицию.

```go
a := []int{1, 2, 2, 3}
i := 0
for i < len(a) {
	if a[i] == 2 {
		a = append(a[:i], a[i+1:]...)
	} else {
		i++
	}
}
```

После исправления `a` равно `[1, 3]`. Такой способ удаления сохраняет порядок, но может потребовать `O(n²)` времени из-за сдвига оставшихся элементов.
